## 全局编程、工程目录与语言选择规则

用户于 2026-11-04 指定：以后所有工程的新建、代码生成和修改都按以下规则执行。规则存放于 `{{RULES_DIRECTORY}}/`，不依赖某个业务工程目录。先读该目录 `README.md` 的适用说明，再按任务读取对应文件，不每次加载全部历史规范。

- **编码格式**：遵守 `CODE_FORMAT.md` 对当前语言的规定。默认代码 4 空格缩进；C++/C# 大括号换行，Java/JS/TS 起始大括号同行；命名、注释和分号分别按语言执行。保留现有一致风格和公开接口，禁止无关全库格式化。
- **工程目录**：C++/C# 混合项目遵守 `CPP_CSHARP_PROJECT_LAYOUT.md`；自有源码放 source，第三方依赖使用 thidparty（用户指定拼写），默认配置/用户数据/构建中间文件/运行输出/安装包分别放 config/data/build/app/dist。新建目录按实际功能需要，既有项目逐项调整，不强制迁移框架或第三方仓库布局。
- **职责与独立性**：界面、应用流程、算法和外部适配分开；布局生成文件与手写事件代码分开。每个应用有独立入口、依赖、构建、发布和说明，不依赖 Forge IDE 或其他应用的私有文件。
- **算法语言**：默认优先 C++ 算法库。Python 仅用于直接关联 AI 模型训练、微调、推理、导出等功能，或用户明确指定的任务；“由 AI 编写”不属于此例外。传统图像、点云、标定、几何、体积算法优先 C++。细则见 `CPP_PYTHON_RULES.md`；现有 UI 和脚本保留各自技术栈，不自动重写。
- **跨语言边界**：C++ 核心独立于 UI 和 Python；C# / Python 通过明确的 C ABI 或必要的独立绑定层调用，避免维护重复生产算法。接口说明单位、布局、所有权和失败语义。
- **方法注释**：遵守 `METHOD_COMMENTS.md`；所有具名函数/方法（含私有、构造、事件和局部函数）有用途说明，复杂方法体解释关键步骤、约束、失败处理与资源生命周期。不得只给公共接口加注释或机械逐行翻译。
- **可读性**：使用业务名称、明确单位，复杂算法说明公式和假设；不吞异常，不把未知/失败当有效零值。新增或重构按 `AI_CODE_GENERATION.md` 自查，不添加无用抽象层。规范来源按需查看 `CODING_STANDARDS_CATALOG.md`。
- **适用范围**：文档中的原项目语言版本、框架和测量业务约束只属于相应项目，不能推广为全部新工程的固定要求。用户当前明确指令、项目兼容性及有效局部约定按任务处理；不擅自改变算法、ABI、持久化格式或工具链。
- **落实方式**：新独立应用将适用规则复制到项目 docs，由项目 AGENTS.md 引用；构建不依赖本机全局规则路径。修改旧工程仅处理任务涉及部分，验证如实报告，不宣称未执行的格式/静态检查已通过。
- **人工可维护性**：遵守 `READABLE_CODE.md` 通用规则及当前语言章节；项目/文件/类/方法/变量使用业务语义命名，类型和所有具名方法有准确注释，复杂实现说明约束和失败处理。保留公开 ABI、配置、反射/绑定与语言版本；旧工程按任务涉及模块改进，不以批量改名或机械注释代替可读性。
