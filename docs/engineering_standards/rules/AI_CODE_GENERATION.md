# AI 可读、可维护代码生成约定

适用：本工作区后续开发及修改。目标是让接手者容易定位功能、理解数据流、修改规则和验证结果。既有工程按当前任务逐模块改善，不自动全库重写。本文件是工程约束，不是新模型、自动分析器或质量认证。

## 1. 开始前明确改什么

先读当前模块、调用入口、项目编译配置和相关测试，再确定：

- 本次具体输入、输出、异常情况和验收行为。
- 哪个文件负责界面，哪个负责流程，哪个负责计算或外部访问。
- 当前可复用实现和必须保持的接口、单位、配置、线程与资源生命周期。

小修改无需长设计文档；跨模块修改用简短文字列出调用链及各模块责任。不能未读旧实现就并行增加一套同名功能。信息不足时明确假设，不偷偷填默认值以制造成功结果。

## 2. 让调用顺序容易读懂

- 入口体现真实业务步骤；复杂细节放入具名函数。一个函数负责一个可描述的任务，计算函数尽量显式接收输入并返回结果。
- 按输入校验、主要流程、结果输出的顺序组织。错误条件可提前返回，避免层层嵌套主流程。
- 提取重复且含义一致的规则；外观相似但业务不同的逻辑不强行合并。
- 不使用布尔参数串表达多个模式，优先枚举或含义明确的配置字段；兼容已有公开接口时在内部转换。
- 不依赖隐式全局变量、上次按钮点击状态或控件文本决定算法结果。确需状态时注明归属、修改位置及生命周期。
- 禁止为追求短代码堆叠三元表达式、复杂链式调用、带副作用的条件或一行多条语句。

函数超过约 60 个有效代码行、文件超过约 500 行、嵌套超过 3 层时，作为人工检查信号：检查是否混合职责。它们不是硬性通过标准；生成布局、数据表、清晰的状态处理和性能关键循环可以保留，并说明理由。不把一个连贯过程切碎成大量无意义转发函数。

## 3. 命名、数据和注释

- 使用业务词汇，避免宽泛的 `ProcessData`、`Helper`、`Manager` 承载无关功能。简短循环索引可以保留 `i`，对外数据必须有明确名称。
- 保持模块已有命名风格；不为了风格统一破坏公开 ABI、序列化字段或历史配置。
- 像素、毫米、立方厘米、比例及百分数在名称或类型中区分，例如 `heightMm`、`volumeCm3`、`loadRatio`、`loadPercent`。
- 配置阈值集中命名，说明来源和有效范围；算法中不散落无解释的常数。
- 公共接口注释说明用途、输入输出、合法范围、单位、坐标、所有权、线程要求、失败语义中与该接口有关的部分。
- 复杂算法注释说明公式、物理假设、选择原因和误差边界。中文注释优先便于当前维护者理解，标识符使用明确英文。
- 注释须随代码更新；不要逐行复述赋值、用大段注释掩饰混乱实现，或用“已完成”注释代替实现。

- 所有具名方法（含私有方法、构造函数、事件及局部函数）须有用途说明；复杂方法体说明关键步骤、约束与原因。各语言格式、例外与检查口径见 [方法与方法体注释](METHOD_COMMENTS.md)。

## 4. 分开职责，控制抽象数量

| 责任 | 应放内容 | 不应放内容 |
| --- | --- | --- |
| 界面与绑定 | 布局、输入、触发操作、展示状态 | 测量公式、相机协议、数据库访问 |
| 应用流程 | 调度、取消、会话、状态转换 | 控件绘制、几何积分细节 |
| 算法与业务 | 分格、积分、规则、结果语义 | 窗口引用、按钮状态、相机打开 |
| 外部适配 | 相机 SDK、文件、网络、资源释放 | 擅自修改业务判定 |

只有实际存在这些职责才拆分对应模块，不创建空层。接口用于隔离外部依赖、替换实现或有价值的测试，不要求每个类都有接口。生成布局和手写事件分开，重新生成不得覆盖业务代码。应用必须独立构建与运行，不依赖 IDE 的私有文件。

## 5. 状态和错误必须说得清

- 区分未执行、无数据、无效、有效零值和有效非零值；测量额外区分实测、估算、未知范围。
- 对外返回可判别的错误或状态，在适当边界记录诊断；不空捕获异常、不把失败替换为成功。
- 日志保留操作、原因及相关帧号/会话，避免逐帧重复无界刷屏。用户界面展示可行动信息，技术细节进入日志。
- 明确谁创建、谁释放、何时取消；禁止 UI 线程同步等待长任务和无界队列。结果关联原输入会话，旧会话不能覆盖新结果。
- C++ 用 RAII 管理资源，异常不穿越 C ABI；C# 用 IDisposable、using 或 finally 释放资源；TypeScript 异步操作明确失败与取消路径。

## 6. 针对现有技术栈的边界

- 容积工程保持 C++17、C# 5 / .NET Framework 4.8；不得为了使用新语法升级运行环境。
- Forge IDE 保持其项目声明的 TypeScript、Electron 等版本与进程边界；不得把其框架要求套用到测量程序。
- C++ / C# 共享结构的大小、布局、单位、缓冲区长度及所有权属于接口契约。
- 算法可读性重构不得改变积分口径、补偿假设、阈值、点云尺度、箱规匹配或缺测处理；需要改变时作为明确的行为修改说明并验证。
- 第三方代码保留来源及许可证，不为了本规则批量格式化；生成产物通过生成器修改。

## 7. 每次修改后的自查与验证

先阅读自己修改后的调用链，再逐项回答：

1. 接手者从入口能否定位关键规则？新名称是否准确？
2. 本次修改是否混入另一项职责、重复实现或不必要抽象？
3. 输入、单位、状态、错误、资源及并发边界是否明确？
4. 方法声明（含私有、事件与局部函数）是否有说明？方法体的关键步骤、假设、并发与失败处理是否有准确注释？
5. 是否保持要求的兼容性，是否有无关格式化或隐藏行为变化？
6. 哪个测试或样本能证明此次行为？这个验证能否在代码出错时失败？

按改动选择实际验证：编译与已有相关检查；算法使用已知真值和边界/回归样本；跨语言改动检查 ABI；流程改动检查取消、失败与会话；模板改动编译生成工程。小文案、注释改动无需新增形式化测试。工具未安装或未运行必须明说。离线通过不代表现场精度通过。

交付只报告与本次有关的文件入口、行为、验证结果及剩余限制。不得仅凭“符合规范”、行数下降或格式检查通过宣称质量提升。

## 8. 可直接复用的任务提示词

> 请按本项目 AI_CODE_GENERATION.md 开发。先读取已有入口和相关模块，确定输入输出、职责及兼容约束，再实现最小完整修改。代码以维护者易读为优先：业务命名明确、数据单位明确、界面与功能分开、失败与未知不混同；复杂算法解释公式和假设。不要添加无用层、吞异常或改动无关功能。完成后阅读修改后的调用链，执行与变更匹配的验证，并说明改动入口、验证结果和未验证项。可读性重构不能隐式改变计算行为。

本文件可复制到其他独立项目的 docs 目录，由该项目 AGENTS.md 引用；复制后按实际技术栈修改第 6 节，不依赖本工作区存在。规则需要代理实际读取并执行，不能保证任何 AI 自动遵从。
