# 编码规范汇编与项目执行标准

版本：1.0；整理日期：2026-11-04。

适用对象：AI 生成代码、人工开发与代码评审。主目标是可读、可维护、正确；以当前任务涉及代码为实施范围，不批量改写历史工程。本文件是选取并适配的项目标准，不是任何厂家的完整手册，也不代表现有代码已全量合规。

## 二、执行优先级

1. 用户当前明确要求与项目实际接口、部署、数值契约优先；规范不能被用来暗改行为或擅自升级环境。
2. 本文件中的“必须”是本项目约束，不等于原厂所有条目都属强制。“建议”需要结合场景判断。
3. 修改旧文件延续其一致风格；新模块采用该语言约定。禁止为统一命名破坏配置字段、序列化名称或 C ABI。
4. 与子项目现有规范共同执行；出现实质冲突先记录差异并结合任务解决，不静默选择影响行为的做法。
5. 例外只需在相关变更说明中写明规则编号、原因、范围和验证方式，不引入额外审批流程。

## 三、通用可读性与维护规则

以下均为项目适配条文；来源栏表示参考依据。

| 编号 | 级别 | 项目规则 | 来源与检查方法 |
| --- | --- | --- | --- |
| G01 | 必须 | 名称准确表达业务，避免随意缩写和拼音混用；循环索引等局部惯用短名可保留。 | ALI 命名风格；读名称能否理解用途。 |
| G02 | 必须 | 量值明确单位，区分像素、mm、cm³、比例和百分数。 | LOCAL；检查参数、字段和换算位置。 |
| G03 | 必须 | 一个函数完成一个明确任务，入口能读出处理顺序；不把多个无关功能塞入 Helper/Manager。 | LOCAL；阅读入口及直接调用。 |
| G04 | 必须 | 界面只处理布局、输入和展示；流程调度、算法、外部访问分开，算法不得引用控件。 | LOCAL；检查依赖方向。 |
| G05 | 必须 | 公共接口注释说明用途、输入输出和失败方式；有单位、坐标、线程或所有权约束时一并说明。 | ALI 注释规约的跨语言适配；检查接口文档。 |
| G06 | 必须 | 复杂算法说明公式、假设及边界；代码变更同步更新注释。 | ALI 注释规约 + LOCAL；对照实现阅读。 |
| G07 | 建议 | 简单代码靠清楚命名表达，不逐行重复注释；不长期保留无解释的注释掉代码。 | ALI 注释规约；人工审阅。 |
| G08 | 必须 | 不用有效零值表示未知、失败或未执行；错误返回能被调用方区分。 | LOCAL；状态与异常用例。 |
| G09 | 必须 | 不空捕获异常、不无证据回退成功；界面给出可行动提示，详细原因写入适当日志。 | LOCAL；失败路径检查。 |
| G10 | 必须 | 配置阈值有名称、范围和来源；不得为使测试通过而偷偷放宽容差。 | LOCAL；配置及回归差异。 |
| G11 | 必须 | 生成布局与手写绑定分开；重新生成不覆盖手写业务，发布不依赖 IDE 私有目录。 | LOCAL；生成工程构建及路径检查。 |
| G12 | 建议 | 仅抽取确有共同含义的逻辑；不为每个类强制增加接口、基类和转发层。 | LOCAL；逐项说明抽象用途。 |

## 四、C++ 算法与 DLL

| 编号 | 级别 | 执行要求 | 依据 / 验证 |
| --- | --- | --- | --- |
| CPP01 | 必须 | 用 RAII 或明确的封装管理资源；分配与释放方式配套，禁止重复释放和释放后访问。 | SAFE R2.1–R2.6、R2.12；生命周期测试/适用静态检查。 |
| CPP02 | 必须 | 在除法和数值转换前检查合法性；外部输入检查长度、边界、有限性及必要的溢出风险。 | SAFE R1.13、R1.15 + LOCAL；边界与非法输入用例。 |
| CPP03 | 必须 | 外部 SDK 资源按 SDK 约定释放；借用指针说明有效期，不取得不属于自己的所有权。 | SAFE 资源管理思想的项目适配；SDK 契约核对。 |
| CPP04 | 建议 | 普通功能优先函数而非宏；宏参数不带隐含副作用。 | SAFE R3.2.10、R3.3.1；检查调用表达式。 |
| CPP05 | 建议 | 避免重复实现本可由成员自动完成的复制和析构；资源型对象明确复制/移动策略。 | SAFE R5.1.10 及资源语义；编译与对象生命周期验证。 |
| CPP06 | 必须 | C ABI 固定字段含义、布局和调用约定；不得传递 STL 容器或让 C++ 异常跨越边界。 | LOCAL；结构大小、偏移和 P/Invoke 契约检查。 |
| CPP07 | 必须 | 输入缓冲区是否可修改、谁分配输出、如何释放、线程能否并发都写入接口契约。 | LOCAL；契约测试。 |
| CPP08 | 必须 | 算法库不打开相机、访问 UI 或悄悄修改原始帧；保持 C++17。 | LOCAL；依赖和输入前后对照。 |
| CPP09 | 建议 | 性能热点复用缓冲区、避免无效重复计算；优化必须与同批样本的数值和耗时对照。 | SAFE R2.22 + LOCAL；性能与结果回归。 |

不全面采用 SAFE 的“避免动态分配”等严格选项：图像缓冲区和第三方 SDK 有实际需要，按容量上限、所有权及热路径约束执行。模板、必要内联和 SDK 接口也不能为了泛化规则被破坏。

## 五、C# 界面与应用层

| 编号 | 级别 | 执行要求 | 依据 / 验证 |
| --- | --- | --- | --- |
| CS01 | 必须 | 新类型、方法、属性采用 PascalCase，局部变量/参数采用 camelCase；字段风格延续模块。 | CS 命名约定的项目选取；命名检查。 |
| CS02 | 必须 | 明确访问级别；新代码四空格缩进、大括号换行，分支保留花括号。 | CS 格式约定的项目适配；格式检查。 |
| CS03 | 建议 | 类型不明显时显式写出类型；不为了短代码滥用 var 和复杂链式表达式。 | CS 类型清晰性约定；人工阅读。 |
| CS04 | 必须 | 公共 API 用 XML 文档注释；描述参数、结果及适用约束，复杂实现补中文原因说明。 | ALI 文档思想跨语言适配 + LOCAL；接口检查。 |
| CS05 | 必须 | 原生资源用适用的 IDisposable、using、finally 或 SafeHandle 管理；事件订阅有必要的解除位置。 | LOCAL；重复打开/关闭与异常路径验证。 |
| CS06 | 必须 | 不在 UI 线程执行耗时计算或同步等待后台任务；更新控件切回 UI 线程。 | LOCAL；调度和取消路径检查。 |
| CS07 | 必须 | 会话失效后不能发布旧结果；帧号与输入匹配，处理队列有界。 | LOCAL；会话切换回归。 |
| CS08 | 必须 | P/Invoke 类型、字符编码、结构对齐与 C ABI 对应；不得猜测 bool/指针的跨语言大小。 | LOCAL；ABI 测试。 |
| CS09 | 必须 | 当前容积应用保持 C# 5 / .NET Framework 4.8；不用 nameof、record、using 声明等超出版本的语法。 | LOCAL；现有工具链编译。 |

冲突处理：阿里 Java 的小写方法名、不以下划线开头等约定不套用到 C#。微软 Runtime 的新语法示例和 Unicode 转义偏好也不全盘移植；本项目保留可读中文注释、既有本地化方式和 UTF-8 编码。现有 API 名称不因风格变化而重命名。

## 六、Java 与 TypeScript 的适用范围

- **JAVA01（必须）**：实际 Java 工程采用 ALI 的 Java 命名、注释及适用规则；对照项目 JDK 与框架。没有 Java 代码时不引入 Java 工具链。
- **JAVA02（必须）**：P3C 规则检查必须注明工具/规则版本及实际结果；不能由“已阅读手册”推导为“检查通过”。
- **TS01（必须，本地规则）**：Forge IDE 保持 TypeScript strict，IPC 输入在运行时校验，不能仅依赖类型断言。
- **TS02（必须，本地规则）**：渲染界面不直接拥有文件和进程权限；异步操作处理失败、取消和过期结果。
- **TS03（必须，本地规则）**：生成模板的布局与手写绑定分开，并实际编译生成的 C# 工程。

本节不是阿里或华三 TypeScript 标准。

## 八、AI 生成与交付检查单

执行流程：阅读已有实现 → 明确当前修改边界 → 编写最小完整功能 → 阅读修改后的调用链 → 执行相关验证 → 报告结果。详细操作沿用项目现有 AI 生成约定，不重复建立第二套流程。

- [ ] 本次功能入口、输入输出及模块责任明确。
- [ ] 名称、单位、状态及错误可读，无暗藏默认成功。
- [ ] 函数职责清楚；过长函数检查是否混杂职责，不机械按行拆分。
- [ ] 注释解释物理/业务假设，已与实现同步。
- [ ] 无不必要架构层、重复算法、无关格式化。
- [ ] UI、流程、算法、外部访问没有反向耦合。
- [ ] 资源、并发、取消、跨语言契约已按变更检查。
- [ ] 运行环境、ABI、配置及原有计算口径得到保留，行为变化已说明。
- [ ] 实际执行适用验证，结果与未验证内容分别记录。

只需报告适用项及发现的问题，不为每个小修改生成长篇模板。纯文档和小文案修改检查内容与链接即可。

## 九、工具与验收的边界

| 检查 | 可用方式 | 能证明什么 / 不能证明什么 |
| --- | --- | --- |
| 格式 | .editorconfig、适用的 clang-format/C# 格式化器/Prettier | 格式一致；不能证明职责合理或数值正确。 |
| 语言与部分缺陷 | 编译器、适配项目的 clang-tidy、C# 分析器、TypeScript 检查 | 覆盖已启用规则；不是全部厂家规范自动检查。 |
| Java 规则 | 适配版本的 P3C/PMD | 仅用于实际 Java 工程和已配置规则。 |
| 算法与接口 | 已知真值、边界、缺测、回归样本、ABI 检查 | 验证对应样本及契约；不能代替完整现场测试。 |
| 可维护性 | 人工或 AI 逐项阅读调用链和差异 | 判断结构与语义；不能用工具绿灯代替。 |

本次交付仅整理并接入文档，未新增扫描器、插件、CI 或全库审计。工具不存在必须报缺失；第三方、自动生成代码与历史问题应明确检查范围，不能通过全面关闭告警制造通过记录。
