# 全局工程开发规则

2026-11-04：用户要求以后所有工程的新建和修改遵守已确认的代码格式、目录和语言选型规则。本目录为独立的全局副本，不依赖任何具体业务工程存在；全局入口由接收端 Agent 的用户级规则文件引用；安装时绑定实际路径。

| 当前工作 | 读取规则 |

## 跨项目适用说明

- 核心默认：传统算法库优先 C++；Python 仅用于直接涉及 AI 模型的功能或用户明确指定的任务。“AI 编写代码”不是使用 Python 的理由。
- 按语言应用格式规则；界面、流程、算法和外部适配分别组织。应用独立构建、发布、运行。
- `source/thidparty/config/data/scripts/docs/build/app/dist` 是相关新建自有工程的默认职责划分。已有项目、第三方仓库和框架规定的目录不强行重排；本次改动按所属模块逐步规范，不为目录图制造空层。
- 文档里的 C++17、C# 5/.NET Framework 4.8、Forge IDE 行宽 110、箱规/点云等要求来自原工程，只适用于相应项目；不能把它们当成所有新项目的版本或业务约束。其他项目保留其已声明的编译器、框架、平台和工具链。
- 新项目采用模板前检查语言/工具版本和平台；模板存在不等于格式化器或静态分析器已安装。
- 当前明确用户要求和项目具体兼容约束优先处理。项目局部规则有差异时按实际任务说明并解决，不擅自破坏 ABI、配置或计算行为。
- 新建独立应用时，把适用规则复制到工程 docs，并在工程 AGENTS.md 中引用工程内相对路径。编译和运行不能依赖本机 `.codex` 目录。已有项目无需为了此次全局设置批量插入文档。
- 只修改请求范围，相关验证如实报告。此处是代理指导规则，不是已安装到所有 IDE 的强制检查插件，也不是对历史代码的全量合规证明。

维护时更新本全局副本；项目携带的副本按当前任务同步，不静默批量覆盖各项目的本地约定。
