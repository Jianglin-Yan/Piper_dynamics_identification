# C++ / Python 选型与目录规则

## 1. 默认选择

**算法库优先使用 C++。只有直接涉及 AI 模型，或用户明确指定 Python 时，才采用 Python 实现相应功能。**

“AI 直接相关”指模型训练、微调、模型推理、模型导出以及与这些任务直接关联的数据处理；不等于“这段代码由 AI 编写”，也不包括项目中只要有一个 AI 模块就把所有功能改成 Python。

| 工作内容 | 默认语言 |
| --- | --- |
| 图像增强、传统图像识别、点云滤波、平面拟合、标定、几何计算、容积积分 | C++ 算法库 |
| 原生设备适配、性能关键数据处理 | C++；已有适配接口按工程保留 |
| 模型训练、微调、推理、导出及直接相关处理 | 可使用 Python；已有合适的 C++ 推理方案继续使用 |
| 用户明确要求的 Python 工具或程序 | Python，限定指定范围 |
| C# 界面、TypeScript IDE、现有构建脚本 | 保留各自语言，不因算法优先 C++ 而全部改写 |

不能仅以“Python 写起来快”或“某库使用方便”作为新增 Python 算法模块的理由。新建非 AI 工具也不能默认转用 Python；优先现有工程工具链。已有 Python 不自动全库重写，按后续任务范围逐步处理。

## 2. 混合调用边界

- C++ 核心不依赖 Python 解释器，独立编译、测试和发布。
- 对外共享算法以 C ABI 暴露，Windows 输出 DLL，Linux 输出共享库；只声明实际构建验证的平台。
- C# 通过 P/Invoke、Python 可通过 ctypes 调用同一套 C ABI，不各自复制一份生产算法。
- 确需 Python 专用扩展时，可单独增加 pybind11 等绑定层；绑定依赖只属于该层，不进入核心算法库。
- 接口明确单位、坐标、数组布局、长度、所有权、错误及版本。C++ 异常不跨语言边界。
- Python 中与 AI 输入输出直接相关的前后处理可以就近实现；独立通用几何、滤波、测量算法仍优先复用 C++。
- 不以写临时文件、反复启动 Python 子进程作为默认逐帧算法调用方式。

## 3. 目录规则

在现有独立工程规则上按需增加 Python 部分，不创建空目录：

```text
ApplicationName/
├─ source/
│  ├─ native/                    C++ 核心算法及 C ABI
│  │  ├─ include/                对外声明
│  │  ├─ src/                    算法实现
│  │  └─ tests/                  原生测试
│  ├─ python/                    仅在符合选型条件时存在
│  │  ├─ application_name/        Python 包：按实际功能拆分
│  │  │  ├─ bindings/            ctypes 包装（按需）
│  │  │  └─ ai/                  模型相关代码（按需）
│  │  └─ pyproject.toml          Python 包和依赖声明
│  ├─ bindings/python/           原生 Python 扩展源码（使用时才创建）
│  ├─ managed/                   C# 应用（已有工程保留）
│  └─ tests/python/              Python 及跨语言测试（按需）
├─ thidparty/                    第三方 SDK、绑定库、离线包及环境说明
├─ models/                       模型文件与版本说明（按需）
├─ config/                      默认参数
├─ data/                        用户数据、采集记录或训练数据
├─ scripts/                     构建、启动和打包入口
├─ build/                       构建中间文件
├─ app/<平台>/                  发布程序及所需运行依赖
└─ dist/                        安装包或压缩包
```

Python 包目录使用小写下划线。保留用户指定的 `thidparty` 拼写。纯 Python 包装和原生扩展只选择实际需要的方式，不能为目录完整同时制造两套重复接口。

## 4. 环境与交付

- Python 项目声明解释器版本和依赖，记录可复现的版本解析结果；沿用已有包管理方式，不无故同时引入多套管理器。
- 开发虚拟环境属于可重建本地产物，不提交源码仓库；离线安装包、解释器分发说明按需放入 thidparty，不把跨机器复制虚拟环境作为交付方式。
- 不含 Python 功能的生产程序不增加 Python 运行依赖；需要 Python 的程序明确携带或安装方式，不依赖开发者个人环境。
- 模型标明来源、版本与许可；现场和训练数据不默认装入发布包。
- C++ / Python 编码格式沿用项目按语言制定的规则。当前容积核心继续保持 C++17，本规则不触发编译器或框架升级。

本规则约束后续语言选型及新文件位置，不表示现有程序已经迁移或新增 Python 支持。
