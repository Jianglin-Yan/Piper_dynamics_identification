# G8 控制的 PiPER 动力学试采

## 独立幅度与速度缩放（2026-10-29）

```bash
bash real_robot/pilot.sh sim --standing --trajectory multisine --scale 0.5 --speed-scale 0.5 --max-seconds 600
```

`--scale`为幅度比例，`--speed-scale`为播放速度比例，均允许0<S≤1；不传速度参数默认1，兼容旧行为。计算为 `q=q_anchor+amplitude_scale*(q_source(speed_scale*t)-q_anchor)`；参考速度乘 `amplitude_scale*speed_scale`，参考加速度乘 `amplitude_scale*speed_scale²`。两个参数均0.5时，相比原先50%幅度/原速：动作范围相同，速度减半，加速度降为四分之一，测试60秒变120秒，两端包络各5秒变10秒，基频0.2Hz变0.1Hz。准备、回收、制动策略和保护阈值不随速度参数缩放。

相同参数已通过正常120秒及中止仿真；参考峰值约0.970rad/s、2.320rad/s²。reference_plan.json标注原始/实际时长与频率，test_manifest/test_samples/test_quality均记录速度比例；离线导出继续按实际接收时间求实测加速度。终端及仿真窗口显示两种比例。

```bash

```

## 测试数据与临时 scale（2026-10-29）

准备和回收流程沿用已实机通过的版本。新增独立实验数据集，仅在 `TESTING` 采集；正常结束或中止离开该状态即停止，制动/回程/失能不进入实验数据。`samples.jsonl`、全程RX/TX和events仍是诊断记录。新运行的 `analyze` 默认只分析测试数据；旧运行没有独立测试文件时才兼容全程诊断。

`--scale S`（0<S≤1，默认1）只缩放测试相对起点的位移：`q=q_start+S*(q_nominal-q_start)`，参考速度和加速度同乘S，频率与时长不变。准备、回收和固件保护不随scale改动。默认pilot入口是原有J6±5°窗口正弦；S=0.25即±1.25°。六关节原库轨迹必须显式选择 --trajectory multisine，见本页顶部。

```bash
# 相同配置，先仿真、再人工确认实机；仍等待G8
bash real_robot/pilot.sh sim --standing --scale 0.25
bash real_robot/pilot.sh hardware --standing --scale 0.25
```

可按25%→50%→100%分轮测试，每一档先仿真，再在同档实机观察；scale是缩幅，不是只跑前25%时间，也不是固件速度百分比。缩幅数据主要用于调通与评估，不能假定其激励充分。

测试文件：

| 文件 | 内容 |
|---|---|
| test_samples.jsonl | 约100Hz，仅TESTING；六轴q、qd、电流、候选力矩、参考q/qd/qdd、发送位置及时间、每类反馈接收时间和年龄、温度/电压/使能/故障/夹爪；实机还增加电机原始位置、分开的驱动/电机温度及母线电流 |
| test_raw_can.jsonl | 按实际接收时间截取测试窗口，保留原CAN全速帧；仿真没有CAN，文件为空 |
| test_signals.csv / test_signals.npz | 测试信号导出；原向量仍为异步快照，按逐轴q_times/drive_times/low_times对齐，不冒充同步测量 |
| test_acceleration.csv | 统一时间网格上的实测速度离线导数qdd_est和逐轴有效标志 |
| test_manifest.json | 代码提交/是否有本地改动、配置、scale、测试窗口与中断原因、负载说明、单位和信号定义 |
| test_quality.json | 样本/有效比例、控制最大间隔、实机各CAN帧频率与最大间隔、加速度估计方法等 |

采样窗口是测试状态的主机时间区间 `[start,end)`；进入TESTING那次快照仍来自READY/ARMING，故不当作实验样本；退出TESTING那次快照及随后制动回程也不写入测试快照。原始CAN按窗口独立截取，保留实际帧率。异常数据保留但带质量标记，中断试验会标注原因。

`qdd_ref`是解析参考加速度，不能作为实测加速度；`qdd_est`由实测速度及逐轴接收时间离线生成，使用100Hz网格和11点三阶Savitzky-Golay导数，只是预览估计。边缘和缺帧间隔被屏蔽为NaN及false，正式辨识前仍需评估滤波、延迟与信号定义。原始电流/速度/CAN永久保留，方便重算。候选力矩未标定，manifest明确标注尚不能直接视为辨识可用数据；实机不存在可直接记录的真实M/C/g矩阵，不伪造这些真值。

收尾失能后自动导出，不在活动控制中运行离线滤波。需要重新导出时：

```bash

python -m real_robot.analyze runs/某次记录
```

## 统一收尾：回位 → 静止 → 失能确认 → 退出（2026-10-29）

正常完成、LB+RB、Ctrl+C / SIGTERM、手柄断开及可受控处理的持续速度/电流告警，统一取消试采、平滑制动（需要时）、回到启动位置的最近合法点，确认半秒位置稳定，再撤去六轴驱动力矩、确认失能后退出。不会保持使能悬空退出。LB+RB 是软件受控中止，不是硬件急停。

优先要求每轴距合法回位目标 ≤0.5°；精确到位10秒超时后，仅当每轴 ≤3° 且半秒位置变化 ≤0.20°，才接受“附近”，打印实际相对原始启动位置的六轴差值。更远或仍在运动则不卸力、不退出。**启动位置应是蜷缩且有可靠支撑、可撤去驱动力矩的停放位置**；程序无法仅靠六轴角度判断是否接触支撑物。若从悬空姿态启动，回到该角度并不代表可以安全失能。

MOVE J 没有本程序已核查的力矩渐卸接口；这里“泄力/失能”是发送 `0x471 [7,1,0,0,0,0,0,0]`，使六个机械臂关节撤去驱动力矩，不控制夹爪、不关闭24V总电源。它不是另发 `0x150=01` 阻尼急停后让臂回落，也不调用 reset 来收尾。[官方 disable 说明](https://github.com/agilexrobotics/pyAgxArm/blob/master/docs/piper/piper_api.md) 提醒失能会移除动力，因此必须先停放。

终端出现 `DISABLING` 后继续接收反馈：要求六轴低速状态全部晚于失能命令，连续150ms均为失能；不是命令发送成功就退出。2秒仍未确认则显示 `DISABLE_UNCONFIRMED`，继续发送失能请求、监视并记录，**不会因超时自行关闭程序**，不会重置、使能或再发位置目标。确认后才输出 `DONE：六轴已确认失能...`，关闭采集与CAN。

真实驱动故障、严重超速、反馈失联等情况下不盲目回位：保留故障停止，继续监视。如果当前仍通电且无法确认启动位置附近静止，提示 `PARK_UNCONFIRMED` 并等现场支撑、放回；确认停放后失能。若已收到六轴新鲜失能反馈，则不会为了回位重新使能。严重故障最终仍以 `FAULT` / 非零退出记录，即使失能已确认。通信完全中断时无法用CAN证明失能，程序会留在监视状态，需要现场处理，不能宣称已安全完成。

仿真同步加入失能后的重力运动；简化模型没有真实支撑接触，所以只能预览撤力后的趋势，不能验证停放支撑。新版流程尚未做实机失能验收。

## 反馈阈值与停止

规划速度仍为 0.12 rad/s，它用于生成轨迹，不再直接乘 1.5 作为原始速度反馈的单帧急停门槛。

| 反馈条件 | 处理 |
|---|---|
| 速度超过 0.30 rad/s | 告警记录，继续执行 |
| 同一关节超过 0.60 rad/s，连续 150 ms | 反馈、使能、跟踪及制动路径有效时，取消轨迹，沿当前已发送参考速度制动，回位后失能退出；不发送电子急停 |
| 单帧速度超过 1.20 rad/s | 严重超速，进入故障停止 |
| 电流短时超过原软件阈值（J1–3：2 A，J4–6：1.5 A） | 告警记录；同一关节连续 200 ms 才请求制动回位 |
| 电流超过上述阈值 2 倍，或真实驱动故障/反馈失联等 | 故障停止；电子急停可能导致重力回落 |

这些是本次试采的软件监测参数，不是电机额定值，也不改驱动限流、固件角度限制或碰撞等级。到位判断使用半秒位置窗口（默认最大变化 0.20°），不要求原始速度每一帧都小于 0.025 rad/s；启动原始速度检查为 0.15 rad/s。阈值分别由 `feedback_speed_*`、`feedback_current_stop_duration_s`、`feedback_current_emergency_multiplier` 配置；更快的正式轨迹需采用与规划速度匹配的反馈阈值。

所有健康受控停止均执行本页顶部的回位失能流程；停止原因保留在 `stop_reason`。不能可靠执行回位时进入故障监视，不自动恢复或重新使能。

若上次已经进入电子急停，先在蜷缩机械臂获得支撑后单独恢复，再运行测试：

```bash
# 此命令立即失电，只恢复一次；不使能、不发送运动目标
bash real_robot/pilot.sh recover --supported
# 仍等待手柄：LB+X 准备，READY 后 LB+Y；LB+RB 中止回位
bash real_robot/pilot.sh hardware --standing
```

恢复使用独立入口并要求 `--supported` 明确确认支撑；运动程序不会替你调用。ARMING 还会确认新鲜的六轴使能及稳定 100 ms 的 CAN 模式。

当前范围：等待手柄 → 准备到起点 → 单轴小幅激励 → 制动/回位 → 确认失能 → 结束；配套 MuJoCo 预览和原始数据记录。没有开放多轴激励，也没有把试采数据自动拟合为惯性参数。

本目录是独立入口，不依赖旧仿真工程的绝对路径。原库 excitation/data_collector/regressor/identify/validate 保持原样，后续以这里采集的真实数据接入原库回归器。

## LB+X 固定抬起到试验姿态

针对 20261028_174140_737162 记录中的“J6 目标增加、实际位置不变”，新增分阶段准备模式；该记录最终 J6 目标 15.421°、实际 12.418°，触发原 3° 跟踪阈值，六轴位置无变化，使能反馈已打开。原因尚不能仅凭此记录确定，不能归因于增益或自动放宽误差。

```bash
# 在自己的终端先预览；不打开 CAN
bash real_robot/pilot.sh sim --standing
# 实机启动条件检查，不使能、不运动
bash real_robot/pilot.sh hardware --standing --preflight-only
# 实机：启动后等待手柄；仅在你按 LB+X 时执行准备动作
bash real_robot/pilot.sh hardware --standing
```

`--standing` 与 `--from-current` 互斥。固定工程试验起点为 `[0,45,-60,0,0,0]°`，可通过配置 `standing_start_deg` 修改，但必须在各轴内部余量内。它不是厂商认证安全姿态；仿真几何与周边碰撞限制仍见下文。

LB+X 的顺序：

1. 以新鲜测量值初始化目标并等待六轴使能，保持 3° 跟踪阈值。
2. 若停放 J2/J3 仍有不超过 3° 的边界偏差，先下发一个合法、就近的 MOVE J 终点（通常 J2=J3=0，其余保持），由固件以 2% 速度比例进行短过渡。这一小段使用固件规划，不是主机把非法目标连续插值到区间外。若 8 秒内未到位，进入故障监视收尾，不进入大幅准备动作或试采。
3. 边界点稳定后，使用受速度/加速度约束的五次多项式平滑抬起。按当前默认参数，从记录中的折叠位置到 READY 约 19 秒，仅为仿真参考。
4. 实测到位并稳定后才出现 READY。提前按 LB+Y 会被忽略并提示，需到位后重新按。LB+Y 后仍仅 J6 ±5° 激励。

LB+RB 在准备、试采和回程中都有效。正常或中止后回到启动时显示的回位点；若原始启动值小幅超出固件范围，则按已确认策略回最近合法点，并显示差值。站姿不会被偷偷用作回位基准。原始读数始终保留，实机正常回位与再次运行仍需要验收。

发送兼容性：原实现只在使能时发送一次 0x151；现每次位置目标均附带模式/速度报文，与 [官方 V2 关节控制示例](https://github.com/agilexrobotics/piper_sdk/blob/master/piper_sdk/demo/V2/piper_ctrl_joint.py) 的循环方式一致。是否是本次不动的根因仍待实机对比验证。保持现有固件、Kp/Kd、设备零位与限位，不自动清错或重新使能。

新版故障提示包含关节编号、目标角度、实际角度和误差，便于直接读终端定位。

## 从当前蜷缩姿态直接进行实机 J6 试采

用户已指定从当前停放角度启动。此路径需要显式 `--from-current`：

```bash
cd ~/Documents/41Piper/Piper_dynamics_identification
bash real_robot/pilot.sh hardware --from-current
```

程序先读取实际六轴角度并等待，LB+X 提示无需移动，全部松开后 LB+Y 才使能并开始 J6 ±5° 试采。正常结束或 LB+RB 中止后回到这次启动时的角度。

当前姿态模式只允许 J6、`start_deg=null`、幅度不超过 5°、频率不超过 0.1 Hz：

- J2 低于配置下限、J3 高于配置上限，各允许最多 3° 的停放反馈偏差；其他方向或关节的越界仍拒绝。
- J1–J5 的位置目标始终固定为本次启动读数，不从文件套用停放角度，不清零。其实际反馈允许偏离启动值最多 0.5°；使能前若任一轴相对启动值变化超过 0.1°则拒绝，要求重新启动读取。
- J6 仍受原限位与 5° 余量约束，整条 ±5° 轨迹必须通过检查。
- 设备固件、零位、限位和碰撞检测等级均不改写。该模式按操作者的明确指令接受现有保护配置（当前碰撞检测为 0），终端打印它；`workspace_checked` 与 `collision_policy_reviewed` 的历史字段不自动改成 true。普通指定起点模式仍使用原来的检查。
- 若固件拒绝当前保持目标或报告故障，停止并锁定，不清错重试。软件预检通过不代表固件已经接受目标，或实机运动已经通过验收。

只验证实机启动条件，不读取按钮动作，也不使能或运动：

```bash
bash real_robot/pilot.sh hardware --from-current --preflight-only
```

`PREFLIGHT_ONLY` 表示仅检查完成，不是实机运动测试通过。此模式的 MuJoCo 预览也可用 `--sim --viewer --from-current`；只有仿真中的保持关节限位按锚点设置，不影响设备。

## 快速使用

在本机终端执行：

```bash
cd ~/Documents/41Piper/Piper_dynamics_identification
# 首先检查手柄，完全不连接 CAN
/home/shin/anaconda3/envs/lerobot/bin/python -m real_robot.run --monitor-pad --max-seconds 300
# Ctrl+C 退出后，运行独立仿真；也不连接 CAN
/home/shin/anaconda3/envs/lerobot/bin/python -m real_robot.run --sim --viewer --max-seconds 300
```

终端必须保持可见。仿真窗口显示状态、当前试采关节角度和目标角度。默认 J6、±5°、0.1 Hz、20 秒，前后各 5 秒平滑包络，动作很小。仿真初始姿态是用于演示的 `[0,45,-60,0,20,0]°`，不是当前实机姿态，也不是下发给实机的默认目标。

| 输入 | 行为 |
|---|---|
| LB+X | 准备。`start_deg=null` 时使用程序启动姿态，终端提示无需移动；指定起点时走受限五次多项式过渡。|
| LB+Y | 只有 READY 才开始；未准备时仅提示。|
| LB+RB | 最高优先级受控中止：取消激励，按已发送参考位置和参考速度制动，检查回程后返回已显示的合法回位点；不把原始速度尖峰当成制动初速度。|
| Ctrl+C / SIGTERM / 手柄设备断开 | 反馈正常时制动、回位、确认失能后退出；无法受控回位时进入故障监视。|
| 关闭运行中的仿真窗口 | 执行受控停止及失能收尾，不因关闭窗口直接中断收尾。|

组合键之间先全部松开。启动时已经按住的键不会触发准备/开始。短按事件从 evdev 队列逐个读取，不依赖键盘式长按；同一批事件中 LB+RB 优先。完成后实机回位并确认六轴失能才退出；仿真窗口额外保留最多 60 秒供观察，也可手动关闭。再次测试需重新启动程序，重新读取初始姿态。

**LB+RB 不是安全认证急停。** 健康状态下按你的要求执行制动回位；反馈失联、驱动故障、失能、跟踪异常、回程越界等条件下，禁止回位，尝试发送固件快速停止并锁定。固件电子急停允许机械臂阻尼回落，不是悬空保持；若 CAN 已断，软件不能保证停止指令送达。蓝牙断连检测依赖 Linux 驱动上报，不能保证无线丢包瞬间响应；独立硬件急停仍需可用。

## 配置和停止逻辑

- `joint`：1–6，一次一个关节。首轮默认 J6。
- `start_deg`：null 表示启动姿态；否则为六轴绝对目标，不能省略中间过渡。
- `amplitude_deg`、`frequency_hz`、`duration_s`、`ramp_s`：窗口化单正弦参数。
- 速度、加速度上限默认均 0.12（rad/s、rad/s²）；预检覆盖去程、激励和回程，命令也逐次检查边界。路径预检为密集离散采样，不是连续时间形式化证明。
- 100 Hz 控制/快照记录，原始 CAN 接收按各帧真实到达频率记录；本机角度与高速反馈约 200 Hz，驱动低速状态约 40 Hz。
- 持续的中等速度/电流越阈值、正常中断和手柄移除请求制动回位并失能；严重超速/电流、反馈超时、真实状态异常、跟踪误差、温度/电压异常、接收溢出、日志写入失败仍进入故障停止。参数是工程监测阈值，不是厂商认证的安全限值。
- 独立看门狗检测控制循环/接收异常；发出快速停止后设置锁存，后续位置和使能命令被拒绝。它不能保证 Python 进程崩溃、系统停机、CAN 或蓝牙故障下的安全。
- 位置目标在使能前初始化到当前测量值；新鲜的完整六轴使能及稳定 CAN 模式确认后才进入准备。
- 不控制夹爪、不重新标零、不自动解除急停或清错，不在停止后自动重试。只有显式 `recover --supported` 入口发送一次恢复/重置。
