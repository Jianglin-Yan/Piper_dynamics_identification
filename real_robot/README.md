## 终端输出约定（2026-11-03 重构）

运行脚本的终端只保留四类输出，详细政策与阈值看本文件，不再重复打印：

- **header**：启动时一次性打印标题、控制方式（MIT／MOVE J）、MIT 前馈比例、任务说明；随后一行给出启动角度与回位点。
- **状态**：每次阶段切换一行 `[时间] 状态`，如 `[10:03:45] PREPARING`。
- **测试过程**：只打印路径里程碑 `移动到期望位置 k/n`，不再逐秒打印误差。
- **前馈渐变**：每秒一行 `力矩渐变 0.10 进度 50% 当前最大 |FF| … Nm`，开始/结束各一行说明。
- **警告**：一行 `[时间] 警告 内容`，不中断。
- **故障**：固定五段——原因、部位、实测、处理、下一步，便于对照现场。

所有输出同时写入 `events.jsonl`。完整数据仍在 `samples.jsonl`、`test_signals.npz`／`csv`。

公共角度设置：`measurement_angle_tolerance_deg=10°`，实测反馈硬边界按固件／配置原始限位向外各扩10°，不是在内缩后的规划边界上加10°。例如J6原始±120°，TESTING反馈接受±130°；运动目标仍按原规划余量5°（通常±115°）检查，固件限位不变。启动姿态余量仍单独为10°，准备／回收保留既有启动走廊；J6单轴模式的其余保持轴仍遵守漂移限制。静态、正反、负载和激励测试共用此配置。

### 统一MIT测试：纯PD与比例重力前馈

入口为 `test_mit.sh`。准备、固定小轨迹、回收全程使用MIT原生Kp/Kd，禁止MOVE J回退。`--ff-scale 0`是纯PD，`0.25`在同一任务中加入25%重力前馈；默认名义PiPER模型，`--gravity-model identified`改用本次balanced-v2辨识结果。没有额外挂重；夹爪不下发指令。

```bash
# 第一步：先看纯PD仿真，再运行纯PD实机
bash real_robot/test_mit.sh sim --ff-scale 0
bash real_robot/test_mit.sh hardware --ff-scale 0
# 第二步：两边都只改变前馈比例，轨迹和增益调度相同
bash real_robot/test_mit.sh sim --ff-scale 0.25
bash real_robot/test_mit.sh hardware --ff-scale 0.25
```

LB+X以启动时实测角度作为第一目标，直接使能MIT并平滑到 `[0,45,-60,0,0,0]°`；到位后3秒内前馈从0增加到指定比例，准备与测试使用相同增益，终端显示READY后LB+Y才执行固定轨迹。测试轨迹为五个姿态：标准姿态→`[10,60,-45,0,0,0]°`→加腕部`[10,60,-45,12,15,20]°`→肩肘回摆`[-10,30,-75,12,15,20]°`→标准姿态，四段各≥3.5秒，纯测试共18.98秒（不含准备与回位）。六个关节都参与：J1 ±10°、J2 30–60°、J3 −75–−45°、J4 0–12°、J5 0–15°、J6 0–20°，末端行程约0.19 m，J2重力力矩变化约5.0 Nm、J3约1.9 Nm。J1/J4/J6本身几乎不产生重力力矩（量级0.01 Nm），加进来是为了姿态覆盖和现场观察，评价仍以J2/J3/J5为主。准备／回位仍用0.08（rad/s、rad/s²），测试段用0.15，使动作在同样时长内更明显；0.15 rad/s下惯量项仍远小于重力项。纯PD也经过相同3秒阶段，前馈请求全程为0。

渐入／渐出期间机械臂保持静止，只有PD维持姿态，容易让人以为程序卡住。因此两个阶段各自打印开始说明、结束说明，并每秒打印一次当前比例与六轴请求前馈力矩（`FF_RAMP_IN_START/IN/IN_DONE`、`FF_RAMP_OUT_START/OUT/OUT_DONE`）；`--ff-scale 0`时明确提示前馈比例为0、无重力前馈。

正常结束：在终点保持目标，用3秒撤去前馈、保持统一PD增益，再MIT回收、失能。LB+RB／Ctrl+C／手柄断开：下个正常控制周期前馈请求直接清零，用相同PD增益与无扰参考制动，再MIT回收失能。无扰参考在协议单位下使切换前后合成PD＋前馈请求尽量连续；边界限制、量化、时延与执行器特性仍可能产生瞬态，不声称实机无冲击。真正驱动故障或通信失效不能强行回收，保留原故障失能退出通道。LB+RB是软件受控中止，不是安全认证急停。

2026-11-03 增益修订：统一回到官方标准参数 **Kp=10、Kd=0.8（六轴、准备/测试/回收同一套）**。此前为提高到位精度试过 J2/J3/J5=15/1.2 和 20/1.6，实机分别出现关节嗡鸣与踢腿（J3/J5 单周期 1° 跳变、电流 3.3–3.7 A），已否决。现在不再用提高增益换精度，而是把到位容差放宽：准备与 MIT 回位都接受 8°（`mit_prepare_tolerance_deg`、`mit_park_tolerance_deg`）。依据是仿真空载静差约 6.3–6.5°、实机在 10/0.8 下约 J3 1°、J5 4°，仿真与实机并不一致，用仿真容差卡实机会过紧。

| 阶段 | J1–J6 Kp | J1–J6 Kd |
|---|---:|---:|
| LB+X准备／保持 | 10 | 0.8 |
| 固定轨迹测试／前馈渐入渐出 | 10 | 0.8 |
| 正常回收／LB+RB受控中止回收 | 10 | 0.8 |

真正故障急停仍发送固件0x150停止指令，该指令不携带Kp/Kd，不等同于PD受控中止。
`--mit-gain-scale 0.5..1`默认1；显式指定时统一缩放准备、测试和回收增益，不再切换为高增益。
MIT 回位目标改为**启动时的实测姿态**（即使它比固件限位超出一两度）：MIT 下发的是关节阻抗目标，不是 MOVE J 的端点，使能时本来就保持这个姿态，所以回位可以直接回到原处。MOVE J 分支仍回最近合法点。失能前增加 **2 秒刚度释放**（`mit_release_s`，仅实机）：kp/kd 从 10/0.8 平滑降到 0，让机械臂落到启动支撑面上，不再在失能瞬间突然下沉。仿真没有支撑模型，跳过释放，直接失能。

纯PD有重力静差，MIT准备到位及开始测试前的位置检查采用8°；误差仍完整记录，不代表轨迹精度为8°。回位判据沿用MOVE J的`settle_error_deg=2.8°`，但MIT回位改用独立的8°释放窗口`mit_park_tolerance_deg`：10/0.8 下仿真空载静差约6.3–6.5°，原3°/5°窗口会超时故障。该窗口只用于MIT回位，不改普通MOVE J的回位判据。公共反馈限位仍是固件／配置原始边界外扩10°，启动姿态余量10°、最近合法点回位与失能逻辑保留。软件同时监测PD＋前馈合成力矩估计、实际电流和既有故障硬线。力矩估计只是驱动侧PD的代理量，因此：D项使用限幅到±0.6 rad/s的实测速度（`mit_estimate_velocity_limit_rad_s`），单周期速度尖峰不会把估计抬到上限；超过预算须连续`mit_budget_exceed_duration_s`（默认0.10 s）才故障，首次超限只打印`BUDGET_WARNING`并带上关节号和数值。2026-11-02 的 `20261102_175700_205288` 就是单周期J2尖峰把估计推到16.11 Nm（上限16.0）而中止，按新逻辑回放只有1个周期超限，不会停。首次运行要求六轴已失能；若上一程序还带电保持，本入口拒绝自动模式切换或强制失能。

MIT线上前馈按官方旧固件协议为关节Nm÷b÷c；不再额外乘减速比，与官方`move_mit`的`t_ff/b/c`、`FloatToUint(-8,8,8)`逐行一致。固件单轴`t_ff`上限为8×b×c（J1–3 32 Nm，J4–6 6.51 Nm）；启动时会打印本次比例下测试路径上的预计最大|FF|与该上限，方便上机前确认规模。8位编码的力矩分辨率约0.25 Nm（J1–3）／0.05 Nm（J4–6），所以低比例下前馈是台阶式增加，不是连续值。`ff_scale=0`表示前馈请求严格为0，旧8位编码仍有量化零点残差。原始Kp/Kd直接下发，仿真假设PD输出按b×c折算，实际增益和时序仍需实机小范围验证；仿真从使能开始就开启真实重力，没有隐藏补偿。官方源码依据见 `assets/mit_official/source.json`。

仅TESTING写入测试数据集；准备／渐入／渐出／回收记录在会话日志。各阶段会话JSONL和测试JSONL包含MIT的q/qd参考、协议Kp/Kd、前馈比例／重力／前馈Nm、线上值、量化后前馈、PD与合成力矩估计。测试NPZ／CSV有同名字段，估计量不冒充传感器真值。原CAN、电流、反馈时间戳、温度和使能状态继续保留。旧 `test_gravity.sh` 已转向此入口，默认比例0.25；旧MOVE J→MIT实机入口停用。


接收／退出修订：短暂CAN接收丢帧仅告警、保留累计计数和数据缺口标记；接收线程不退出。磁盘记录与接收分离；新反馈持续超时、总线错误等仍故障停止。结束时逐轴失能1–6，确认六轴反馈后退出；已确认失能且未遗留电子急停的故障会话，下次可正常启动，无需例行reset。进入收尾后不再响应LB+X／LB+Y；不会在故障后自动重新使能。仅TESTING的数据计入实验，丢帧受影响样本无效，并在test_quality中标明。

本轮软件限制调整：六轴启动反馈允许相对查询／配置限位偏离最多10°，先以原边界过渡进入合法区间；不改零位、固件限位或碰撞设置。运动跟踪10°告警，超过35°持续0.2s后受控制动回位；实测角度允许超出原始限位10°再硬停，轨迹目标仍使用原合法范围。J6单轴试采的其余保持轴漂移容差放宽至2°。速度、电流、温度及通信硬线不因本次成功运行而上调；规划余量和跟踪偏差优先告警。以上均为工程阈值，不是厂商认证安全极限。

### 自助退出（所有三个脚本共用）

- 正常运行按一次Ctrl+C：按原流程停止、回位、失能退出。
- 故障卡在PARK_UNCONFIRMED，或受控回位无法完成：按Ctrl+C查看提示，可靠支撑后再按一次Ctrl+C，立即在当前位置失能；确认六轴反馈后退出，不要求人工搬回启动点。不会复位或重新使能。
- 若CAN完全中断、停在DISABLE_UNCONFIRMED：先可靠支撑并切断机械臂电源，确认已失电后在原终端输入`POWER_OFF`回车。保存`motors_disabled_confirmed=false`及操作者断电确认后异常退出；不伪造失能反馈。重复Ctrl+C不会冒充断电确认。
- 连续多次Ctrl+C不再被吞掉；已排队的按键只触发一次提示，避免提示出现前的按键误作支撑确认。主循环和异常收尾循环都响应退出输入。

历史payload记录中J6失能、J1–J5使能时，MOVE J目标没有执行。最新方案已按操作者明确要求改为六轴使能、J6保持启动角度；不涉及MIT或力矩控制。

## 统一收尾：回位 → 静止 → 失能确认 → 退出（2026-10-29）

正常完成、LB+RB、Ctrl+C / SIGTERM、手柄断开及可受控处理的持续速度/电流告警，统一取消试采、平滑制动（需要时）、回到启动位置的最近合法点，确认半秒位置稳定，再撤去六轴驱动力矩、确认失能后退出。不会保持使能悬空退出。LB+RB 是软件受控中止，不是硬件急停。

优先要求每轴距合法回位目标 ≤0.5°；精确到位10秒超时后，仅当每轴 ≤3° 且半秒位置变化 ≤0.20°，才接受“附近”，打印实际相对原始启动位置的六轴差值。更远或仍在运动则不卸力、不退出。**启动位置应是蜷缩且有可靠支撑、可撤去驱动力矩的停放位置**；程序无法仅靠六轴角度判断是否接触支撑物。若从悬空姿态启动，回到该角度并不代表可以安全失能。

MOVE J 没有本程序已核查的力矩渐卸接口；这里“泄力/失能”是发送 `0x471 [7,1,0,0,0,0,0,0]`，使六个机械臂关节撤去驱动力矩，不控制夹爪、不关闭24V总电源。它不是另发 `0x150=01` 阻尼急停后让臂回落，也不调用 reset 来收尾。[官方 disable 说明](https://github.com/agilexrobotics/pyAgxArm/blob/master/docs/piper/piper_api.md) 提醒失能会移除动力，因此必须先停放。

终端出现 `DISABLING` 后继续接收反馈：要求六轴低速状态全部晚于失能命令，连续150ms均为失能；不是命令发送成功就退出。2秒仍未确认则显示 `DISABLE_UNCONFIRMED`，继续发送失能请求、监视并记录，**不会因超时自行关闭程序**，不会重置、使能或再发位置目标。确认后才输出 `DONE：六轴已确认失能...`，关闭采集与CAN。

真实驱动故障、严重超速、反馈失联等情况下不盲目回位：保留故障停止，继续监视。如果当前仍通电且无法确认启动位置附近静止，提示 `PARK_UNCONFIRMED` 并等现场支撑、放回；确认停放后失能。若已收到六轴新鲜失能反馈，则不会为了回位重新使能。严重故障最终仍以 `FAULT` / 非零退出记录，即使失能已确认。通信完全中断时无法用CAN证明失能，程序会留在监视状态，需要现场处理，不能宣称已安全完成。

仿真同步加入失能后的重力运动；简化模型没有真实支撑接触，所以只能预览撤力后的趋势，不能验证停放支撑。2026-10-29后续实机正常和中止流程均已确认失能，首轮120秒六轴实机也正常失能。

## 反馈阈值与停止

| 同一关节超过 0.60 rad/s，连续 150 ms | 反馈、使能、跟踪及制动路径有效时，取消轨迹，沿当前已发送参考速度制动，回位后失能退出；不发送电子急停 |
| 同一关节连续 100 ms 超过 1.20 rad/s | 严重超速，进入故障停止 |
| 电流超过告警线（持续线的 0.6 倍，J1–3：1.8 A，J4–6：1.5 A） | 告警记录，继续执行 |
| 电流超过持续线（J1–3：3 A，J4–6：2.5 A） | 同一关节连续 300 ms 才请求制动回位 |
| 同一关节连续 50 ms 超过持续线 1.5 倍（J1–3 4.5 A，J4–6 3.75 A） | 受控制动、回位、失能（不立即故障） |
| 真实驱动故障/反馈失联/通信中断 | 故障停止；电子急停可能导致重力回落 |

单帧尖峰不再直接判为严重超速：2026-11-02 的记录 `20261102_161924_734045` 在 READY 保持时出现单帧 J2=−1.302 rad/s，下一帧即回到 −0.536 rad/s，机械臂外观无异常；旧判据立即故障停止。现要求同一关节连续超过 1.20 rad/s 达 `feedback_speed_emergency_duration_s`（默认 0.10 s）才故障，期间的 0.60 rad/s／150 ms 持续层仍然独立生效。100 ms 是工程折中，不是安全认证值；阈值仍由 `feedback_speed_*` 配置。

这些是本次试采的软件监测参数，不是电机额定值，也不改驱动限流、固件角度限制或碰撞等级。到位判断使用半秒位置窗口（默认最大变化 0.20°），不要求原始速度每一帧都小于 0.025 rad/s；启动原始速度检查为 0.15 rad/s。阈值分别由 `feedback_speed_*`、`feedback_current_stop_duration_s`、`feedback_current_emergency_multiplier`、`feedback_current_emergency_duration_s` 配置；更快的正式轨迹需采用与规划速度匹配的反馈阈值。

所有健康受控停止均执行本页顶部的回位失能流程；停止原因保留在 `stop_reason`。不能可靠执行回位时进入故障监视，不自动恢复或重新使能。

若上次已经进入电子急停，先在蜷缩机械臂获得支撑后单独恢复，再运行测试：

## 配置和停止逻辑

- `joint`：1–6，一次一个关节。首轮默认 J6。
- `start_deg`：null 表示启动姿态；否则为六轴绝对目标，不能省略中间过渡。
- `amplitude_deg`、`frequency_hz`、`duration_s`、`ramp_s`：窗口化单正弦参数。
- 速度、加速度上限默认均 0.12（rad/s、rad/s²）；预检覆盖去程、激励和回程，命令也逐次检查边界。路径预检为密集离散采样，不是连续时间形式化证明。
- 100 Hz 控制/快照记录，原始 CAN 接收按各帧真实到达频率记录；本机角度与高速反馈约 200 Hz，驱动低速状态约 40 Hz。
- 持续的中等速度/电流越阈值、跟踪误差、正常中断和手柄移除请求制动回位并失能；严重超速/电流、反馈超时、真实状态异常、温度/电压异常、接收溢出、日志写入失败仍进入故障停止。参数是工程监测阈值，不是厂商认证的安全限值。
- 独立看门狗检测控制循环/接收异常；发出快速停止后设置锁存，后续位置和使能命令被拒绝。它不能保证 Python 进程崩溃、系统停机、CAN 或蓝牙故障下的安全。
- 位置目标在使能前初始化到当前测量值；新鲜的完整六轴使能及稳定 CAN 模式确认后才进入准备。
- 不控制夹爪、不重新标零、不自动解除急停或清错，不在停止后自动重试。只有显式 `recover --supported` 入口发送一次恢复/重置。
